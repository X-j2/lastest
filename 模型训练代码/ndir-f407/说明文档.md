# 第一部分 · 概览

## 1.1 系统定位

本固件运行于 NDIR 呼吸气体分析仪的端侧主控，职责有四：

1. **驱动**红外光源并采集双通道 ADC（测量通道 + 参考通道）
2. **换算**双通道比值 → CO₂ 浓度（ppm），经两点线性标定
3. **推理**每 90 秒对累积波形做一次随机森林分类，输出呼吸模式（4 类）
4. **输出**实时波形与诊断结果（OLED 显示 + 串口帧）

## 1.2 硬件平台

### MCU 与时钟

| 项 | 值 | 来源 |
|---|---|---|
| 型号 | STM32F407ZGTx（Cortex-M4 + FPU）| `1.uvprojx` |
| 存储 | 1 MB Flash / 128 KB SRAM + 64 KB CCM | `1.uvprojx` IROM/IRAM 行 |
| 外部晶振 | HSE 25 MHz | `Core/stm32f4xx.h` |

## 1.5 采样时基（架构要点）

**为什么采样放在定时器中断里**：早期版本把 `Delay_ms(40)` 写在主循环末尾，真实采样周期 = 循环耗时 + 40 ms，导致采样率既低于 25 Hz 又随循环内容抖动（OLED 刷屏那次会明显变长）。

AI 链路把"25 Hz / 90 秒 = 2250 点"硬编码进 `FE_RAW_RATE`、`FE_RAW_WINDOW`、`AB_RESP_RATE_SCALE`。采样率偏低会让**峰间距类特征系统性偏低、峰数类特征系统性偏高**，而幅度类特征不变——特征向量内部自相矛盾，比整体缩放更糟。

**修正**：采样移入 TIM3 更新中断（硬件定时器，周期精确 40.000 ms），中断内只做「采集 → 滤波 → 换算 → 入队」，主循环异步排空。此后无论主循环被 OLED、串口还是 AI 推理阻塞多久，采样节拍恒定。

> 详细影响分析与论文表述建议见 `CLAUDE.md` 的「采样时基」节。

|---|---|---|---|---|
| **Flash** | Code + RO-data + RW-data | **284,880 B ≈ 278 KB** | 1 MB | 27% |

## 2.2 `adc` — 双通道 ADC 采集

**文件**：`HARDWARE/adc.c` / `adc.h`

```c
#define ADC_ACT_CHANNEL        ADC_Channel_1   /* PA1 */
#define ADC_REF_CHANNEL        ADC_Channel_2   /* PA2 */
#define ADC_REFERENCE_MV       3300U

void     ADC_DualChannel_Init(void);
uint16_t ADC_ReadAverage(uint8_t adc_channel, uint8_t sample_count);
uint16_t ADC_CountToMillivolt(uint16_t adc_count);
```

**关键参数与时序**：

| 项 | 值 | 计算 |
|---|---|---|
| ADC 时钟 | **21 MHz** | APB2 84 MHz ÷ `ADC_Prescaler_Div4` |
| 采样时间 | 480 周期 | `ADC_SampleTime_480Cycles`（高阻信号源需长采样） |
| 单次转换 | 492 周期 = **23.4 µs** | 480 采样 + 12 转换 |
| 单次采样点总耗时 | **约 1.5 ms** | 2 通道 × 32 次 × 23.4 µs = 64 次 |

**实现要点**：

- F4 必须**先 `ADC_CommonInit()` 再 `ADC_Init()`**（F1 只需后者），公共配置里决定 ADC 时钟分频
- **未做软件校准**：本工程所用标准库为精简版，不含 `ADC_VoltageRegulatorCmd` / `ADC_StartCalibration` / `ADC_CR2_CAL`。改为 3000 次 `__NOP()` 的稳压器稳定延时。对趋势测量影响可忽略，但**属已知偏差来源**
- `ADC_ReadAverage` 返回四舍五入均值：`(sum + n/2) / n`
- `ADC_CountToMillivolt` 返回 `(count × 3300 + 2047) / 4095`

**改动指引**：

- 换采样次数 → 改 `main.c` 的 `ADC_AVERAGE_SAMPLES`（当前 32）。**注意**：它直接决定中断内耗时，见 §4.5
- 提高 ADC 时钟 → 改 `adc.c` 的 `ADC_Prescaler`（上限 36 MHz）

## 2.3 `ndir_math` — NDIR 两点线性标定

**文件**：`HARDWARE/ndir_math.c` / `ndir_math.h`

```c
#define NDIR_AIR_RATIO             1.412f    /* 空气中实测比值 */
#define NDIR_AIR_PPM               450.0f    /* 对应浓度（估） */
#define NDIR_BREATH_RATIO          1.000f    /* 呼气中实测比值 */
#define NDIR_BREATH_PPM          50000.0f    /* 对应浓度（估） */
#define NDIR_MAX_DISPLAY_PPM       50000.0f
#define NDIR_MIN_REFERENCE_COUNT   5U

typedef struct {
    float   ratio;              /* ACT/REF 比值 */
    float   absorbance;         /* 派生量，当前无人使用 */
    float   concentration_ppm;
    uint8_t valid;
} NDIR_Result;

void NDIR_Calculate(uint16_t act_count, uint16_t ref_count, NDIR_Result *result);
```

**算法**（`ndir_math.c:21-37`）：

```
ratio = act / ref                          /* 透光率，越小表示 CO₂ 越多 */
C = AIR_PPM + (ratio - AIR_RATIO) × (BREATH_PPM - AIR_PPM)
                                / (BREATH_RATIO - AIR_RATIO)
```

直线斜率 = 49550 ÷ (−0.412) ≈ **−120267**，即比值每降 0.001，浓度升约 120 ppm。

**三重防护**：`ref_count < 5` → 无效；两比值相等 → 无效（防除零）；`ratio ≤ 0` → 无效。输出夹在 `[0, 50000]`。

> ⚠ **这 4 个常数是厂家初值，未经标准气体标定**（`.h` 注释自述"只能用于样机趋势显示"）。它们决定 ppm 的绝对尺度，进而决定 AI 侧是否能在 `height=12` 寻峰门限下找到呼吸峰。**标定错误会导致分类结果静默全错**——详见 `CLAUDE.md`「端侧标定依赖」节。

**改动指引**：标定后只需改这 4 个常数，其余代码无需变动。

## 2.4 `oled` — SSD1306 显示

**文件**：`HARDWARE/oled.c` / `oled.h`

```c
#define OLED_WIDTH     128U
#define OLED_HEIGHT     64U
#define OLED_I2C_ADDRESS  0x3CU

void OLED_Init(void);
void OLED_Clear(void);
void OLED_Refresh(void);
void OLED_DrawPixel(uint8_t x, uint8_t y, uint8_t color);
void OLED_DrawLine(int16_t x0, int16_t y0, int16_t x1, int16_t y1);
void OLED_DrawChar(uint8_t x, uint8_t y, char character);
void OLED_DrawString(uint8_t x, uint8_t y, const char *text);
void OLED_DrawUInt(uint8_t x, uint8_t y, uint32_t value, uint8_t minimum_digits);
```

**架构（理解性能的关键）**：

```
绘图 API ──► oled_buffer[1024]  (RAM 帧缓冲，纯内存操作，极快)
                    │
             OLED_Refresh()  ──► 软件位翻转 I²C 发送 1024 字节（慢）
```

**所有 Draw\* 函数只写 RAM，不碰 I²C。** 只有 `OLED_Refresh()` 才真正传输。因此：

- `OLED_Clear()` = `memset` 1024 字节，微秒级
- `OLED_DrawConcentrationWaveform()` 画约 128 条线，全部在 RAM，几十微秒级
- **`OLED_Refresh()` 才是全系统最重的单次操作**——8 页 × 128 字节全量重发

**I²C 时序**：`OLED_I2C_Delay()` 是 `for(i=0;i<105;i++) __NOP();`（`oled.c:68-75`）。循环计数器为 `volatile`，编译器无法优化掉，每轮约 6~7 个周期。这个数字按 168 MHz 为等价延时选取。

**改动指引**：

- 降低 CPU 占用 → 减少刷新频率（改 `main.c` 的 `OLED_REFRESH_SAMPLES`），而非改本模块
- 若要根治刷屏开销 → 改用硬件 I²C + DMA（`FWLIB` 已含 `stm32f4xx_i2c.c`，但 F407 的 I²C 有已知勘误需评估）

## 2.5 `tim` — 双定时器：红外 PWM + 采样节拍

**文件**：`HARDWARE/tim.c` / `tim.h`

```c
void TIM2_PWM_Init(void);
void TIM2_PWM_SetDuty(uint8_t duty_percent);
void TIM3_SampleTimer_Init(void);
void App_OnSampleTick(void);        /* 声明在此，实现在 main.c */
```

### TIM2 — 红外光源调制（PA0）

| 项 | 值 |
|---|---|
| 预分频 | `PWM_PRESCALER = 8399` → 84 MHz / 8400 = 10 kHz |
| 自动重装 | `PWM_PERIOD = 9999` → 10 kHz / 10000 = **1 Hz** |
| 通道 | CH1，PWM 模式 1，高电平有效 |
| 初始占空比 | 50%（`main.c` 中调用 `TIM2_PWM_SetDuty(50U)`）|

引脚配置用 F4 的 AF 方式：`GPIO_PinAFConfig(GPIOA, GPIO_PinSource0, GPIO_AF_TIM2)`，模式为 `GPIO_Mode_AF` + 推挽 + 上拉。

### TIM3 — 采样节拍（25 Hz 中断）

| 项 | 值 |
|---|---|
| 预分频 | `SAMPLE_PRESCALER = 8399` → 10 kHz |
| 自动重装 | `SAMPLE_PERIOD = 399` → 10 kHz / 400 = **25 Hz（40.000 ms）** |
| 中断 | `TIM_IT_Update`，NVIC `TIM3_IRQn` 抢占 0 / 子 0 |

**`TIM3_IRQHandler` 定义在 `tim.c`**（不在 `stm32f4xx_it.c`）——与 `SysTick_Handler` 放在 `delay.c` 同理，避免重复定义。

```c
void TIM3_IRQHandler(void)
{
    if (TIM_GetITStatus(SAMPLE_TIMER, TIM_IT_Update) != RESET)
    {
        TIM_ClearITPendingBit(SAMPLE_TIMER, TIM_IT_Update);
        App_OnSampleTick();          /* 回调到 main.c */
    }
}
```

**改动指引**：

- 改采样率 → 改 `SAMPLE_PERIOD`。**必须同步改三处**（见 §4.4）：
  `feature_extract.h` 的 `FE_RAW_RATE` / `FE_RAW_WINDOW`，以及 `ai_bridge.c` 的 `AB_RESP_RATE_SCALE`

```c
#endif
```

**原理**：Cortex-M4 内置 DWT（数据观察点与跟踪单元）的 `CYCCNT` 寄存器随内核时钟自增，**精度到单个 CPU 周期**，无需示波器或占用引脚。初始化需使能 `CoreDebug->DEMCR` 的 TRCENA 位再置 `DWT->CTRL` 的 CYCCNTENA 位。

**换算**：168 MHz 下 **1 ms = 168,000 周期**，故 25 Hz 的采样节拍 = 40 ms = **6,720,000 周期**。DWT 计数器 32 位，约 25.6 秒回绕一次，远大于 40 ms 的采样间隔，无影响（代码用无符号相减，回绕也自动正确）。

**注意事项**：DWT 需调试器连接时才可靠工作；脱离调试器运行可能读不到有效值。若在脱离调试器时读数异常，属已知限制，不影响正常固件。

|---|---|---|

| `AB_WINDOW_SAMPLES` | `FE_RAW_WINDOW` = 2250 | 90 秒 @ 25 Hz |
| `AB_RESP_RATE_SCALE` | `60.0f / 90.0f` | 峰数 → 真实呼吸率 |

**内部缓冲**：

```c
AI_ALIGNED(32) static uint8_t ab_pool[AI_RANDOMFOREST_DATA_ACTIVATION_1_SIZE];  /* 68 B */
static float ab_wave_mmhg[AB_WINDOW_SAMPLES];   /* 2250 × 4B = 9.0 KB */
static float ab_wave_100hz[FE_WINDOW_SIZE];     /* 9000 × 4B = 36.0 KB */
static float ab_feats[FE_N_FEATURES];           /* 12 */
```

**流程**：

| 阶段 | 实现 |
|---|---|
| `AI_Init` | `ai_randomforest_create_and_init(&net, act, NULL)` → 取输入输出缓冲描述符 → 校验数量。**权重自动绑定，第三参数传 NULL** |
| `AI_ProcessSample` | `ab_wave_mmhg[count++] = ppm × 0.00076`；满 2250 触发满窗处理 |
| 满窗处理 | `FE_Resample25To100`（2250→9000）→ `FE_Extract`（12 维）→ `ai_randomforest_run` |
| 结果 | 读 `ab_out[0].data` 为 int32 标签（越界夹到 3）；`feats[8] × 60/90` 算真实呼吸率 |

**两个关键实现细节**：

1. **激活池与输入输出缓冲是同一块内存**。模型导出时启用了 `--allocate-inputs/outputs`，所以 `inputs_get()/outputs_get()` 返回的 `data` 指针**指向 68 字节的 `ab_pool` 内部**。不要另行分配输入输出缓冲区。
2. **`AI_ALIGNED(32)` 不可去掉**。运行库要求激活池 32 字节对齐，ARMCC 下该宏展开为 `__attribute__((aligned(32)))`。

> **`AB_RESP_RATE_SCALE` vs F11 特征**：前者（60/90）用于计算**真实呼吸率**供显示；F11 特征硬编码 `n_peaks × 60/30`（训练端历史遗留）。**两者不可混用**——F11 是喂给模型的数值，改了会导致特征分布偏移。

## 2.9 `feature_extract` — 12 维特征提取

**文件**：`AI/feature_extract.c` / `feature_extract.h`

```c
#define FE_RAW_RATE     25     /* 固件采样率 Hz */

int FE_FindBreathPeaks(const float *x, int n, int sampling_rate, int *peaks, int max_peaks);
int FE_Extract(const float *x, int n, int sampling_rate, float features[FE_N_FEATURES]);
```

**12 维特征顺序**（与训练端 `FEATURE_NAMES` 一致）：

| # | 名称 | 临床含义 |
|---|---|---|
| 0 | Mean CO2 | 波形均值 |
| 1 | Std CO2 | 标准差（ddof=0）|
| 2 | Peak-to-peak | 峰峰值 |
| 3 | Skewness | 偏度 |
| 4 | Peak interval mean | 峰间距均值（秒）|
| 5 | Peak interval SD | 峰间距标准差（秒）|
| 6 | Peak width | 峰宽（秒）|
| 7 | Plateau ratio | 呼气平台占比 |
| 8 | **Peak count** | **呼吸峰数** |
| 9 | Peak amplitude | 平均峰幅 |
| 10 | Wave RR | 自算 RR（硬编码 60/30）|
| 11 | Rhythm confidence | 频率置信度 |

**实现要点**：

- **寻峰忠实复刻 scipy** `find_peaks(x, height=12, distance=int(1.0*sr), prominence=8)`，含局部极大值的**平台取中点**规则（`(i_a + i_b) / 2` 整除）
- **中间缓冲放静态区不放栈**：候选峰数组 4500 × 2 B × 2 个 = 18 KB，本工程栈仅 1 KB 量级，放栈会直接溢出
- **距离筛选用二分插入实现 O(m log m)**，而非朴素 O(m²)——m 可达 3000，朴素实现在中断后主循环里会造成明显卡顿

> ⚠ **F11 硬编码 `60/30`**：训练端 `_feature_wave_rr()` 写死了 `n_peaks × 60.0 / 30.0`（注释称 30 秒窗口，实际窗口 90 秒——历史遗留）。模型是在这个数值上训练的，**端侧必须原样保留**。改为 60/90 会导致特征分布偏移、模型失效。

**已知差异**（不影响分类，论文可写为工程细节）：训练端 scipy 的 `_select_by_peak_distance` 内部用 `np.argsort(priority)`，而 numpy 默认 quicksort **不稳定**——两个候选峰高度**精确相等**时（监护仪波形平台平坦，实测大量存在），保留哪个由排序枢轴决定，**无确定性规则可复刻**。本实现采用确定性规则「峰高降序，同高则位置靠后者优先」。

实测（120 个真实窗口）：F1~F4、F7~F11 共 9 个特征一致到 float32 极限（~5e-8）；F5/F6/F12 三个时间类特征相对误差 <16%；**预测标签 120/120 完全一致**，故无需改动训练端或重新训练。

**改动指引**：本模块与训练端必须逐条对应。修改任何公式前，须同步修改 `features/extract_features.py` 并重新训练模型。

### 数据结构

```c
typedef struct { uint32_t value_q8; uint8_t initialized; } ADC_LowPassFilter;

typedef struct {
    float    ppm;        /* NDIR 浓度，供曲线显示、AI 累积与串口帧 */
    uint16_t act_mv;     /* ACT 通道毫伏，仅供电平显示（不再进串口帧）*/
```

### 共享变量与 `volatile` 规则

**中断与主循环共享的变量必须加 `volatile`**，否则编译器可能把读写优化掉：

| 变量 | 谁写 | 谁读 |
|---|---|---|
| `sample_queue[]` | ISR（`Queue_Push`）| 主循环（`Queue_Pop`）|
| `queue_head` | ISR | 主循环（比较）|
| `queue_tail` | 主循环 | ISR（比较）|
| `queue_overflow` | ISR | 主循环（取值上报）|
| `act_filter` / `ref_filter` | ISR | ISR |
| `sample_tick` | ISR | 主循环（调度判断）|
| `last_act_count` / `last_ref_count` / `last_ndir_result` | ISR | 主循环（OLED 显示）|

**无需 `volatile`**：`concentration_history`、`history_count`、`history_write_index`、`concentration_filter_q8` 等——仅主循环访问。

> **为何不需要临界区**：生产者（ISR）只写 `queue_head`，消费者（主循环）只写 `queue_tail`。双方各自只写一个索引，读对方的索引。单字读写在本平台是原子的，故无竞态。

### 环形缓冲

```c
static void Queue_Push(const SampleItem *item)
{
    uint16_t next = (uint16_t)((queue_head + 1U) % SAMPLE_QUEUE_SIZE);
    if (next == queue_tail) { queue_overflow++; return; }   /* 满：丢弃并计数 */
    sample_queue[queue_head] = *item;
    queue_head = next;
}
```

**容量语义**：数组 64 个元素，但**留一个空槽区分"空"与"满"**，故实际可存 **63 个**采样点 = 2.52 秒。

**溢出必须显式上报**：队列满时 `queue_overflow++`，经串口帧字节 16–19 透出。**绝不静默丢点**——否则又回到"不报错但结果错"的静默失效模式。

### 初始化顺序（`main.c:355-395`）

```c
Delay_Init();               /* 1. SysTick 1ms —— 最先，后续延时依赖它 */
Timing_Init();              /* 2. DWT（未启用 TIMING_DEBUG 时为空操作）*/
TIM2_PWM_Init();            /* 3. PA0 红外光源 PWM */
TIM2_PWM_SetDuty(50U);
ADC_DualChannel_Init();     /* 4. PA1/PA2 */
OLED_Init();                /* 5. PB6/PB7 */
USART1_Waveform_Init();     /* 6. PA9 */
(void)AI_Init();            /* 7. 加载模型（失败不阻止其余功能）*/
/* 8. 显示快照预置为"无效"，避免上电后显示未初始化数据 */
TIM3_SampleTimer_Init();    /* 9. 最后启动采样节拍 */
```

**顺序理由**：TIM3 必须最后启动——前面任何一步未完成时产生采样中断都可能读到未初始化的外设。`AI_Init` 失败时置空句柄，波形采集与串口照常工作，仅 AI 字段保持"无结果"（`frame[11]=0x00`）。

### 采样回调 `App_OnSampleTick()`（中断上下文）

```c
void App_OnSampleTick(void)
{
    SampleItem item;
    uint16_t act_count, ref_count;
    NDIR_Result result;

    Timing_MarkTick();                   /* 记录节拍间隔（调试）*/

    act_count = ADC_ReadAverage(ADC_ACT_CHANNEL, ADC_AVERAGE_SAMPLES);
    ref_count = ADC_ReadAverage(ADC_REF_CHANNEL, ADC_AVERAGE_SAMPLES);
    act_count = ADC_FilterValue((ADC_LowPassFilter *)&act_filter, act_count);
    ref_count = ADC_FilterValue((ADC_LowPassFilter *)&ref_filter, ref_count);
    NDIR_Calculate(act_count, ref_count, &result);

    /* 发布显示快照 */
    last_act_count = act_count;
    last_ref_count = ref_count;
    last_ndir_result = result;

    if (result.valid != 0U) {            /* 仅有效值入队 */
        item.ppm = result.concentration_ppm;
        item.act_mv = ADC_CountToMillivolt(act_count);
        Queue_Push(&item);
    }
    sample_tick++;                       /* 累计节拍 */
}
```

> 📌 **中断内的三条铁律**：
> 1. **严禁**调用 OLED / 串口 / AI 推理——这些是耗时的
> 2. 只做「采集 → 滤波 → 换算 → 入队」
> 3. 当前耗时约 **1.5 ms**（主要是 ADC 的 64 次转换），占 40 ms 周期的 **3.75%**

### 主循环（排空式）

```c
while (1)
{
    /* 唯一的采样消费点 */
    while (Queue_Pop(&item) != 0U)
    {
        History_Add((float)Concentration_FilterValue(item.ppm));
        AI_ProcessSample(item.ppm);      /* 满 90 秒时内部触发推理 */

        waveform_samples_ppm[waveform_sample_index] = (uint16_t)(item.ppm + 0.5f);
        waveform_sample_index++;
        if (waveform_sample_index >= 5U) {
            AI_GetStatus(&ai_status);
            USART1_SendWaveformFrame(waveform_samples_ppm, &ai_status, queue_overflow);
            waveform_sample_index = 0U;
        }
    }

    /* OLED 按节拍刷新，不忙等 */
    if ((uint32_t)(sample_tick - oled_last_tick) >= OLED_REFRESH_SAMPLES) {
        oled_last_tick = sample_tick;
        OLED_DrawMeasurements(last_act_count, last_ref_count,
                              (const NDIR_Result *)&last_ndir_result);
    }
}
```

**要点**：

- **没有 `Delay_ms`**：主循环空闲时自然空转。采样节拍由硬件定时器保证
- `(uint32_t)(sample_tick - oled_last_tick)` 用**无符号相减**，32 位回绕时仍正确（约 5.4 年才回绕一次）
- `last_ndir_result` 是 `volatile NDIR_Result`，传给接受 `const NDIR_Result *` 的函数需强制转换

### 两处滤波

| 函数 | 位置 | 系数 | 作用 |
|---|---|---|---|
| `ADC_FilterValue` | ISR 内 | **1/8** | 对 ADC 原值平滑，抑制采样噪声 |
| `Concentration_FilterValue` | 主循环 | **1/4** | 对换算后 ppm 二次平滑，防 OLED 曲线竖直跳变 |

两者均为 Q8.8 定点一阶 IIR：`state_q8 += (target_q8 − state_q8) / N`。

> **注意**：这两级滤波属**硬件采样链路**，与训练端的信号预处理（短缺口插值 + 5σ 离群点替换）**不是一回事**，端侧未复刻训练端预处理。理由见 `CLAUDE.md`「信号预处理」节。

# 第三部分 · 串口协议

## 3.1 波形帧（64 字节，二进制）

**发送节奏**：每 5 个采样组一帧 = **200 ms/帧（5 帧/秒）**。

| 偏移 | 长度 | 含义 | 编码 |
|---|---|---|---|
| **0** | 1 | 帧头 | 固定 `0xFF` |
| **1–10** | 10 | 5 个 **CO₂ 浓度采样点（ppm）** | 每点 uint16，**大端** |
| **11** | 1 | AI 标志 | `0xAA` = 已有结果；`0x00` = 暂无 |
| **12** | 1 | 分类标签 | 0=正常 1=急促 2=屏息 3=呼吸异常 |
| **13–14** | 2 | 呼吸率 × 10 | uint16，**大端**（如 15.0 次/分 → 150）|
| **15** | 1 | 校验和 | 字节 **0–14** 累加和的低 8 位 |
| **16–19** | 4 | 采样队列累计丢弃点数 | uint32，**大端**，正常恒为 0 |
| **20–63** | 44 | 保留 | 全 `0x00` |

> ⚠ **v2.3 变更（2026-09）**：字节 1–10 由「ACT 通道电压(mV)」改为「CO₂ 浓度(ppm)」。
>
> **为什么改**：原先上位机只拿到 ACT 一路绝对电压，用它做了一套独立标定；而固件用的是 `act/ref` **比值**经两点标定得 ppm。比值法能消除光源老化的影响，绝对电压法不能——两套标定互不相干，上位机画出的波形本身就比固件差。改为直接下发浓度后，两端同源。
>
> **⚠ 不兼容**：帧长度、字节偏移、校验和均未变，校验和照样通过。旧上位机（v2.2 及更早）会把 ppm 当成电压，数值完全错误却不报错。**固件与上位机必须同步升级。**

**解析要点**：

- **多字节字段一律大端序**（高字节在前）
- 浓度单位是 **ppm**（不是 mmHg）。上位机若需 mmHg，按 `mmHg = ppm × 0.00076` 换算（与 `ai_bridge.c` 的 `AB_PPM_TO_MMHG_SCALE` 一致）
- 取值范围 `[0, 50000]`（`NDIR_Calculate()` 内部夹取），装得进 uint16
- **校验和范围是字节 0–14，不含 15 自身，也不含 16–63**
- `frame[11] = 0x00` 表示**开机后前 90 秒**尚未完成首次推理——这是正常的，不是故障
- `frame[16–19]` 是**累计值**（非增量）。若非 0，说明主循环曾被阻塞超过约 2.5 秒，该段波形不可信

**校验和计算**（`usart.c`）：

```c
frame[15] = 0;
for (index = 0; index < 15; index++)          /* 注意上界是 15，不是 16 */
    frame[15] += frame[index];
```

## 4.4 常见改动指引

| 需求 | 改动点 | 连带影响 |
|---|---|---|
| **标定传感器** | `ndir_math.h` 的 4 个常数 | 无——只改这一处 |
| **改 OLED 刷新率** | `main.c` 的 `OLED_REFRESH_SAMPLES`（当前 10 = 2.5 fps）| 仅影响显示流畅度 |
| **改采样率** | `tim.c` 的 `SAMPLE_PERIOD` | ⚠ **必须同步改三处**：<br>`feature_extract.h` 的 `FE_RAW_RATE`<br>`feature_extract.h` 的 `FE_RAW_WINDOW`<br>`ai_bridge.c` 的 `AB_RESP_RATE_SCALE` |
| **增大推理余量** | `main.c` 的 `SAMPLE_QUEUE_SIZE`（当前 64）| 每点约 8 B RAM |
| **改 ADC 平均次数** | `main.c` 的 `ADC_AVERAGE_SAMPLES`（当前 32）| ⚠ 直接决定中断内耗时，见 §4.5 |
| **换模型** | 重新生成 `AI/xcube_ai/`，更新 `1.uvprojx` 的 AI 分组 | 权重数组名与尺寸宏会变，`ai_bridge.c` 中引用的宏需同步 |
| **新增驱动模块** | 新建 `HARDWARE/xxx.c/h` + 写入 `1.uvprojx` + 加 IncludePath | 见 §4.1 注 |

> **为什么改采样率要连带改三处**：AI 链路把"25 Hz / 90 秒 = 2250 点"作为**编译期常量**硬编码。只改定时器会导致重采样倍率错误（当前固定 ×4）与呼吸率换算错误。

### 局限

1. **NDIR 绝对标定缺失（最重要）**
   `ndir_math.h` 的 4 个常数为厂家初值。寻峰门限 `height=12` 是 **12 mmHg 的绝对阈值**，若 ppm 换算整体偏小，所有呼吸峰都会低于该阈值 → F9 峰数=0、F10 峰幅=0 → 模型判定"屏息"，而实际呼吸正常。**全程不报错、不崩溃，串口照常输出，只是结论全错。** 详见 `CLAUDE.md`「端侧标定依赖」。

2. **域差异**
   训练数据来自 VitalDB 气管插管**术中机械通气**病人（主流式二氧化碳仪接在呼吸回路），RR/EtCO₂ 由呼吸机设定；本样机为**自主呼吸**通过测量腔。气流动力学、死腔、响应时间均不同。**这是标定无法消除的分布差异**，故端到端精度不会等于论文报告值。

3. **ADC 未做软件校准**
   本工程所用标准库为精简版，缺 ADC 校准 API。改为稳压器稳定延时。对趋势测量影响可忽略，属已知偏差来源。若后续需精密测量，建议换用完整版标准库补上校准。

4. **中断内 ADC 的取舍**
   `App_OnSampleTick` 在中断里完成 64 次 ADC 转换（约 1.5 ms），占 40 ms 周期的 3.75%。这是为换取采样时基精度而付出的代价——若改为中断只置标志、主循环做 ADC，则采样时刻将再次受主循环负载影响，回到原问题。

5. **端侧未复刻训练端预处理**
   训练端做了短缺口线性插值 + 5σ 离群点替换；端侧未做。理由：固件采样链路本身已有 32 次平均 + 两级 IIR，输出为连续无缺口的平滑序列，不存在 NaN 缺口；5σ 替换主要针对监护仪数据伪迹，本样机链路无此问题。

6. **`absorbance` 字段为死代码**
   `NDIR_Result.absorbance` 计算后无人使用（`main.c` 只用 `concentration_ppm` 与 `ratio`）。保留不影响功能，如需清理可删。
